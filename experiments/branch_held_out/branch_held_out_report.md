# Branch-Held-Out Experiment Report

## Setup

**Goal**: Measure cross-branch generalization by training on one generation branch and testing on the other.

### Data

| Split | Branch | Source | Count | Classes |
|---|---|---|---|---|
| Train A | Pooled (OSS models) | 3rd/oss.jsonl (accepted) | 1,635 | all 7 |
| Test B | GPT-5.4 | 3rd/gpt5.4_shakib + gpt5.4_adiba (accepted) | 764 | all 7 |
| Train C | GPT-5.4 | 3rd/gpt5.4_shakib + gpt5.4_adiba (accepted) | 764 | all 7 |
| Test D | Pooled (OSS models) | 3rd/oss.jsonl (accepted) | 1,635 | all 7 |

### Models

- **Llama3.2-3B-Instruct** — LoRA rank 16, 100 steps, lr 2e-4

## Key Findings

1. **Large generalization gap**: Pooled→GPT-5.4 (0.928 acc) vastly outperforms GPT-5.4→Pooled (0.718 acc). This is expected: pooled branch has 2.1x more training data (1,635 vs 764).

2. **GPT-5.4 branch is harder to learn from**: Despite being the same model architecture, training on GPT-5.4 data yields worse generalization to pooled. Possible reasons:
   - GPT-5.4 notes have different distribution (no PlannedGoal/ClinicalDecision in shakib subset, only 3 and 33 in adiba subset)
   - GPT-5.4 notes are generated by a single model vs. pooled's multi-model diversity

3. **Low-support classes suffer**: PlannedGoal (3 test samples) and ClinicalDecision (31) have poor F1 when testing GPT-5.4 on pooled data, reflecting the sparse GPT-5.4 training data for these classes.

4. **Pooled branch generalizes well**: Training on pooled notes achieves near-perfect F1 on AccessCost (1.000), OtherUnknown (0.975), PatientPreference (0.972), AdverseEffects (0.935), and EfficacyMismatch (0.924) when tested on GPT-5.4 notes.

## Notes

- **Data imbalance**: Training counts differ significantly (1,635 pooled vs 764 GPT-5.4). This is inherent to the benchmark construction.

- **Training cost**: ~3.5 min per model on 1×H200 GPU.
